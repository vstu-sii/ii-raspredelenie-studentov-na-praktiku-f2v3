# ВКР-трекер — AI ENGINEER

ИИ-модуль системы сопровождения выпускных квалификационных работ (ВКР).

AI-часть проекта отвечает за генерацию тем ВКР по профилю преподавателя, интеллектуальный анализ литературы, предварительное ревью материалов ВКР и использование LLM для автоматизации рутинных задач научного руководителя.

## AI-задачи проекта

- генерация тем ВКР с учётом профиля преподавателя;
- проверка новых тем на смысловое сходство с прошлыми;
- анализ и проверка списка литературы;
- предварительный AI-review текста ВКР;
- LLM-review программного кода;
- формирование рекомендаций для научного руководителя.

## Выбранный подход

Для MVP используется связка:

**RAG + LLM + embeddings + детерминированные проверки**

LLM используется для генерации и смыслового анализа.

RAG передаёт модели контекст:
- профиль преподавателя;
- прошлые темы ВКР;
- требования кафедры;
- методические материалы;
- данные о литературе.

Embeddings используются для семантического сравнения тем и документов.

Формальные проверки, где возможно, выполняются обычным кодом и внешними API, чтобы не полагаться только на ответы LLM.

## Кандидаты моделей

Рассматриваются три варианта:

- облачная LLM — основной вариант для прототипа;
- российская облачная LLM — альтернативный вариант;
- локальная open-source LLM — вариант для работы с конфиденциальными данными.

Сравнение проводится по:

- качеству ответа;
- стоимости;
- latency;
- размеру контекстного окна;
- возможности локального запуска.

Подробнее: `docs/model-candidates.md`

## Первый эксперимент

Первый эксперимент проверяет генерацию тем ВКР по профилю преподавателя.

Входные данные:

- научные интересы преподавателя;
- направления исследований;
- используемые технологии;
- предыдущие темы ВКР.

Результат:

- 10 предложенных тем;
- краткая цель каждой работы;
- рекомендуемые технологии.

Темы оцениваются по четырём критериям:

1. соответствие профилю преподавателя;
2. конкретность;
3. реализуемость;
4. отсутствие дублирования.

Критерий успеха: не менее **7 из 10** тем подходят после минимальной корректировки.

Подробнее: `docs/experiments/lab1.md`

## ADR: выбор AI-подхода

Рассматривались:

- прямые prompt-запросы;
- RAG;
- полноценный AI-агент.

Для MVP выбран **RAG + LLM**.

От полноценного агента на первом этапе отказались из-за дополнительной сложности, стоимости и сложности отладки.

### Цена решения

Выбранный подход требует:

- создания базы знаний;
- построения embeddings;
- хранения векторных представлений;
- контроля качества retrieval;
- дополнительной инфраструктуры для Vector DB.

Подробнее: `docs/research.md`
