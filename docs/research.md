# Research — AI Engineer

## 1. Задача

Цель AI-части ВКР-трекера — автоматизировать интеллектуальные операции при сопровождении ВКР:

- генерацию тем с учётом профиля преподавателя;
- семантическое сравнение новых и прошлых тем;
- анализ литературы;
- предварительный AI-review текста и кода ВКР.

Для этих задач рассматриваются прямые LLM-промпты, RAG и агентный подход.

## 2. Прямой LLM-промпт

Самый простой вариант — передавать профиль преподавателя непосредственно в prompt и получать список тем.

Преимущество: минимальная сложность реализации.

Недостаток: модель не имеет доступа к актуальной внутренней базе кафедры, прошлым темам и методическим материалам, если они явно не переданы в контекст.

Источник: официальная документация OpenAI по моделям и работе с контекстом.

## 3. RAG

RAG (Retrieval-Augmented Generation) объединяет языковую модель с внешним поиском по базе знаний.

В оригинальной работе Lewis et al. RAG описывается как подход, объединяющий параметрическую память языковой модели с внешней непараметрической памятью и retrieval-механизмом.

Для нашего проекта внешней базой знаний могут быть:

- профили преподавателей;
- темы ВКР прошлых лет;
- требования кафедры;
- методические документы.

Это позволяет перед генерацией темы находить релевантный контекст и передавать его LLM.

Источник: Lewis et al., “Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks”, 2020.

## 4. AI-агент

Агентный подход позволяет LLM самостоятельно выбирать последовательность действий и вызывать инструменты.

Например, агент может:

1. получить профиль преподавателя;
2. найти похожие прошлые темы;
3. проверить требования кафедры;
4. вызвать LLM;
5. проверить результат дополнительным инструментом.

В документации LangChain агент определяется как система, в которой модель выбирает действия и вызывает инструменты в цикле до достижения условия завершения.

Для MVP такой подход считаем избыточным: появляется дополнительная логика управления инструментами, состоянием и остановкой цикла.

Источник: LangChain Agents documentation.

## 5. Кандидаты моделей

Для прототипа рассматриваются три категории моделей.

### OpenAI

Облачная модель подходит для быстрого прототипирования и предоставляет API, structured output и большие контекстные окна.

Актуальные характеристики и стоимость моделей публикуются в официальной документации OpenAI.

Источник: OpenAI API — Model comparison.

### YandexGPT

YandexGPT рассматривается как российский облачный вариант. Yandex Cloud предоставляет YandexGPT Pro и API для генерации текста.

Источник: Yandex Cloud AI Studio / Foundation Models documentation.

### Qwen3-8B

Qwen3-8B рассматривается как локальная open-source альтернатива. Модель опубликована с лицензией Apache 2.0 и поддерживает запуск через Transformers.

Источник: официальный model card Qwen/Qwen3-8B на Hugging Face.

## 6. Критерии сравнения

Модели будем сравнивать по:

- качеству генерации;
- стоимости запроса;
- latency;
- размеру контекста;
- возможности локального запуска;
- качеству работы с русским языком.

Стоимость облачных моделей нельзя фиксировать один раз на весь проект, так как тарифы могут меняться. Поэтому стоимость должна рассчитываться по актуальным тарифам провайдера.

Источники: официальные страницы тарифов OpenAI и Yandex Cloud.

## 7. Решение / ADR

Для MVP выбран подход:

**RAG + LLM + детерминированные проверки.**

Причины:

1. RAG позволяет использовать внешнюю базу знаний, что соответствует задаче работы с профилями преподавателей, прошлыми темами и требованиями кафедры.
2. LLM подходит для генерации и смыслового анализа текста.
3. Формальные проверки лучше выполнять обычным кодом или API, где результат можно получить детерминированно.
4. Полноценный AI-агент пока не нужен, поскольку основной сценарий можно реализовать фиксированным pipeline без автономного выбора инструментов.

Выбор RAG основан на работе Lewis et al.; устройство агентного цикла — на документации LangChain.

## 8. Цена решения

Выбор RAG увеличивает сложность системы.

Необходимо:

- формировать базу знаний;
- создавать embeddings;
- хранить векторные представления;
- выполнять retrieval;
- контролировать качество найденного контекста.

Таким образом, мы платим дополнительной инфраструктурой за возможность использовать актуальные данные проекта при генерации ответа.
