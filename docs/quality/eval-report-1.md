## 1. Что мы считаем ошибкой

Базовое правило продукта: **ошибка — то, что бьёт по руководителю,
который читает кандидатов тем**. Частота — это статистика; смысл ошибки
определяет тот, кто знает пользователя. Пример: один «blocked на идеальной
теме» — терпимо (руководитель подтвердит вручную); один одобренный дубль
чужой темы — уже удар по доверию к каталогу перед подачей пар (UC-03).

Второе правило: **молчаливая ошибка хуже громкой**. Ответ модели вне
JSON-схемы, который код молча отбросил, — ошибка процесса; явная ошибка
«провайдер недоступен» с повторами — штатное поведение (А1 UC-07).

## 3. Что терпимо, а что нет — решение Product

**Терпимы (руководитель сам закрывает в один клик):** E1, E2, E5, E7.
Эти типы либо ловятся до человека, либо видны с явной причиной. Их
доля в живом прогоне важна для latency-бюджета, но не блокирует пилот.

**Нетерпимы (ломают доверие и последующие UC):** E3, E4, E6, E8.

- E3 (дубли-перефразы) напрямую угрожает UC-03: в приказ попадают пары,
  где две темы — одна работа. Это цена дороже любой метрики точности.
- E4 (промах профиля) убивает саму ценность UC-07: «пустой лист»
  заменяется «листом чужих тем».
- E6 (injection) — риск утечки ключей и непредсказуемого поведения;
  пока устойчивость не доказана на живой модели, фичу в публичный
  контур не выставляем.
- E8 (расхождение спеки и кода) — не ошибка модели, но ошибка команды:
  UI, построенный на «passed», будет показывать статус, которого не бывает.

## 4. Приоритеты улучшений для AI Engineer — по боли, не по частоте

1. **E3 → смысловые дубли.** Подключить embedding-режим (FastEmbed/ONNX
   уже в пайплайне лабы 2) и калибровку порогов на парах
   `similarity_calibration_pairs`. Критерий готовности: перефразированный
   дубль из пары тестов ловится до approve.
2. **E4 → профильность.** Замер в живом прогоне: доля кандидатов,
   релевантных направлениям, по экспертной оценке (даже 20 тем вручную —
   уже выборка). Lexical-overlap оставить как дешёвый prescreen.
3. **E6 → изоляция пользовательского текста.** Поле `focus` — данные,
   а не инструкция: экранирование/отдельная секция промпта, тест на
   seed-кейсе в live-режиме и разбор ответа.
4. **E8 → контракт честный.** Обновить `ai-pipeline.md` (двухсостояний
   gate), добавить approve и export эндпоинты (задачи A-1, A-2 из
   `validation-log.md`) — до начала UI Delivery.
