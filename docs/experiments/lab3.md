# Lab 3 — baseline: реализация и точка измерения

Дата проверки: 29.10.2026. Роль: AI Engineer.

## Что реализовано

Baseline продолжает `docs/ai-pipeline.md` и контракт `api/openapi.yaml`
из `lab2-ai-engineer-design`, commit `717f5843097a7fd0947c582396d736c2fcc481d8`.
Основная модель — `ministral-8b-2512`; 3B выбирается только явно через env.
Промпт `lab3-topics-v1`, temperature 0.2, random_seed 42.
Вход ограничен профилем и 20 прошлыми темами, без ФИО и контактов.
Выход: `teachers: [{teacher_id, titles[]}]`.

SDK Langfuse охватывает каждую попытку. Timeout 40 секунд на попытку,
до трёх попыток на timeout/429/5xx/невалидный structured output;
обычные 4xx не повторяются. Retry-After ограничен 30 секундами.
Задержка запроса включает ожидание повторов. Неизвестные токены не заменяются нулём.
Невалидный ID, число тем, дубликаты, пустые/длинные строки отклоняются.

## Воспроизведение

```bash
python -m pytest -q
python -m ml.experiments.run --mode mock --output docs/experiments/results/lab3-mock
# После настройки Mistral и Langfuse:
python -m ml.experiments.run --mode live --dataset docs/quality/golden-dataset/lab3-seed.jsonl --output docs/experiments/results/lab3-live
```

Любая ошибка live-прогона сохраняется в CSV и даёт ненулевой код завершения.
Версия промпта и SHA256 датасета сохраняются; seed не гарантирует побитовую
повторяемость облачной модели. Прогон перезаписывает CSV/summary/answers,
attempts.jsonl дописывается: для независимого нового эксперимента указывать новую папку.
Приложение к записке: `notebooks/lab3-baseline.ipynb`.

## Что цифры означают для продукта

Сейчас можно утверждать работоспособность интерфейса AI-модуля на
контролируемых ответах. Нельзя утверждать, что модель даёт пригодные
темы за приемлемое время: реальные latency, токены, полнота, профильность,
семантические дубли и доля одобрения человеком пока не измерены.
Стоимость не рассчитывается без фактического usage и актуального тарифа.

Retrieval отсутствует по решению лабы 2: метрики поиска — N/A, их нельзя
смешивать с долей успешных structured outputs. Оценка профильности в коде —
lexical эвристика, а не измеренная точность или экспертная оценка.

Следующий эксперимент: согласованный golden dataset, не менее 100 тем
на модель, отдельно 8B и 3B; p50/p95 задержки с повторами, input/output
tokens, число повторов, доля schema-valid, профильные промахи, дубли,
доля ручного одобрения. Ошибки сохранять даже если весь запуск провалился.

## Явные отклонения и оставшаяся работа

- ADR-002 Product описывает монолит, а выбор модели находится в
  `docs/model-candidates.md` AI-ветки. Реализация следует именно этому выбору;
  не создаётся вымышленный ADR с другим смыслом.
- Embedding-режим пока не подключён. Lexical-only Jaccard и пороги 25/50
  — ограниченный screening, все неблокированные результаты требуют review.
  Проверка синонимов и перефразировок остаётся долгом.
- SQLite-адаптер позволяет проверить сохранение; не заменяет общие миграции Delivery.
- Общие интерфейс/прод/Compose, полный golden dataset и CI eval-порог
  требуют интеграции с Delivery и Quality. Этот PR остаётся draft до
  живых экспериментов и проверки дашборда.
