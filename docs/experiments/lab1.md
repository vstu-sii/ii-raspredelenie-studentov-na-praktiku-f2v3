# Lab 1 — Experiment

## Цель эксперимента

Проверить на реальных данных, способен ли выбранный LLM-подход генерировать темы ВКР по профилю преподавателя и можно ли использовать ответ модели без дополнительного контроля качества.

---

## Гипотеза

Если передать LLM:

- научные направления преподавателя;
- прошлые одобренные темы;
- направление подготовки;
- требования к новой теме,

то модель сможет сгенерировать новые кандидаты тем ВКР.

При этом предполагается, что отдельная проверка качества всё равно может потребоваться для обнаружения смысловых дублей и профильных промахов.

---

## Модель

Использовалась:

**Ministral 3 8B (`ministral-8b-2512`).**

Официальная документация:

- https://docs.mistral.ai/models/ministral-3-8b-25-12

Модель поддерживает Structured Outputs:

- https://docs.mistral.ai/studio/conversations/structured-output

---

## Данные

Для эксперимента использовались реальные профили трёх преподавателей.

Для каждого преподавателя системе были доступны:

- научные направления;
- прошлые темы ВКР;
- требуемое количество новых тем.

Для каждого преподавателя запрашивалось по 5 новых тем.

Итого:

**3 преподавателя × 5 тем = 15 тем.**

---

## Методика

Процесс эксперимента:

1. выбрать преподавателя;
2. сформировать prompt из его профиля и прошлых тем;
3. запросить у Ministral 3 8B новые темы;
4. получить структурированный результат;
5. проверить темы на профильную релевантность;
6. проверить смысловое сходство;
7. зафиксировать темы, которые требуют ручной проверки.

В AI-режиме локальный заранее подготовленный банк тем не использовался.

---

## Результат

Модель успешно сформировала:

**15 из 15 запрошенных тем.**

Все темы этого запуска были получены через Mistral AI.

Локальные демонстрационные темы не подмешивались.

Из 15 тем:

- **10 тем** не получили индивидуальных предупреждений Quality Gate;
- **5 тем** были сохранены с предупреждением и требуют ручной проверки.

Доля тем без индивидуального предупреждения:

`10 / 15 × 100% = 66.7%`.

---

## Примеры проблем

### 1. Смысловое сходство

Для Скоробогатченко Д.А. тема:

> «Разработка многоагентной системы для автоматизированного планирования и мониторинга учебных практик студентов с прогнозированием навыков»

получила пограничную похожесть:

**50/100.**

Это показывает, что LLM способна создать новую формулировку, которая при этом семантически близка к прошлым работам преподавателя.

### 2. Слабое соответствие профилю

Для Щербакова М.В. тема:

> «Разработка системы прогнозирования популярности музыкальных треков на основе анализа социальных сетей и поведенческих данных слушателей»

получила оценку соответствия профилю:

**17/100.**

Система также определила возможное чужое направление.

Это пример того, почему нельзя считать любую технически корректную тему подходящей конкретному преподавателю.

### 3. Неполное покрытие профиля

Для Гаврилова А.Е. генератор сформировал темы, но Quality Gate обнаружил, что в наборе недостаточно представлены области:

- машиностроение и инженерная механика;
- киберфизические системы и технологии.

Это показывает, что одной общей инструкции «учитывать профиль преподавателя» недостаточно.

---

## Что подтвердилось

Эксперимент подтвердил, что LLM может использоваться как генератор кандидатов тем.

Для короткого профиля преподавателя необязательно сразу строить полный RAG-контур: профиль и прошлые темы можно передать непосредственно в prompt.

Подход позволяет получить полный набор кандидатов, но качество результатов неоднородно.

---

## Что не подтвердилось

Не подтвердилась гипотеза о том, что ответ LLM можно использовать без отдельной проверки.

В эксперименте:

**5 из 15 тем (33.3%) потребовали дополнительной проверки.**

Причины:

- семантическая похожесть;
- слабое соответствие профилю;
- неполное покрытие научных направлений.

---

## Архитектурный вывод

По результатам эксперимента для MVP выбран следующий pipeline:

> профиль преподавателя + прошлые темы  
> → Ministral 3 8B  
> → Structured Output  
> → проверка профильной релевантности  
> → semantic similarity  
> → ручное подтверждение преподавателем.

Таким образом, LLM отвечает за генерацию кандидатов, а не за окончательное принятие решения.

---

## Решение по RAG

RAG не исключается из проекта.

Согласно работе Lewis et al., RAG позволяет объединять генеративную модель с внешней непараметрической памятью и полезен для knowledge-intensive задач:

- https://arxiv.org/abs/2005.11401

Однако собственный эксперимент показал, что для первого сценария — генерации тем из короткого профиля преподавателя — исходный контекст можно передавать модели напрямую.

Поэтому RAG планируется использовать позднее для:

- поиска по большому архиву ВКР;
- публикаций преподавателей;
- методических документов;
- проверки литературы.

---

## Итог

Эксперимент дал практическое основание для архитектурного решения.

Для MVP:

- модель: **Ministral 3 8B**;
- генерация: **structured prompt**;
- контроль качества: **отдельный Quality Gate**;
- RAG: **следующий этап при увеличении внешнего корпуса документов**;
- AI-агент: **не требуется для текущего детерминированного pipeline**.

Следующий эксперимент должен сравнить один и тот же набор преподавателей на нескольких моделях и измерять:

- долю профильных тем;
- количество дублей;
- количество тем, требующих ручной проверки;
- время генерации;
- стоимость одного набора.
