# PRD: ВКР-трекер

## Сегмент

Заместитель заведующего кафедрой по учебной части, который лично ведёт
годовой цикл ВКР на кафедре с 20–60 выпускниками и 15–30 руководителями.
Один человек, отвечающий за сроки и документы всего цикла.

Вторичные пользователи (не сегмент, но важны для UX): студенты-дипломники,
руководители ВКР, секретарь кафедры, нормоконтролёр, рецензенты.

## Боли сегмента

1. **Ручная сборка проекта приказа.** Сентябрь–октябрь: 20+ руководителей
   присылают темы почтой и в мессенджерах в разных форматах. Замзав руками
   сводит всё в таблицу и Word-приказ. Замечания ректората → пересборка
   вручную, 2–3 итерации по несколько дней каждая.

2. **Невидимые просрочки просмотров.** Просмотры — окна в несколько дней.
   Если преподаватель не выставил оценку, замзав узнаёт постфактум и пишет
   каждому лично. Картина «кто застрял» отсутствует до конца окна.

3. **Ручная проверка требований к списку литературы.** ≥30 источников,
   ≥20 % зарубежных, обязательные базы. На 40 студентов — 1200+ позиций
   глазами, в апреле–мае, параллельно со всем остальным.

4. **Очередь в нормоконтроль.** Май: все сдают одновременно, нормоконтролёр
   один, при этом большинство замечаний формальные (поля, шрифты, порядок
   разделов) и проверяются машиной быстрее, чем человеком.

5. **Студенты не умеют оформлять источники по ГОСТ.** Каждый источник —
   ручное форматирование, ошибки, библиотека возвращает списки на переделку.

## North Star

**≥ 90 % этапов цикла ВКР закрываются в срок без единого личного
напоминания от замзава** (к концу пилотного цикла, май).

Поддерживающие цели: сборка проекта приказа ≤ 1 дня после подачи всех пар
«студент — тема»; просрочка видна в системе в день возникновения.

## Пределы задержки и цены запроса

| Операция | Латентность | Цена |
|---|---|---|
| Рефчекер, 1 источник (DOI/ISBN/URL → ГОСТ) | ≤ 5 с | ≤ 0,1 ₽ |
| LLM-нормоконтроль, 1 работа (PDF ~60 стр.) | ≤ 3 мин | ≤ 10 ₽ |
| LLM-ревью кода, 1 архив | ≤ 5 мин | ≤ 20 ₽ |

Бюджет пилота на 40 студентов ≤ 3 000 ₽. Деградация: при недоступности
LLM детерминированные проверки продолжают работать, LLM-этапы встают
в очередь с флагом «проверить вручную».

## Связь болей с возможностями команды

- Боли 1–3 закрываются обычной разработкой: трекер статусов и сроков,
  генерация приказа из шаблона, рефчекер по открытым API (Crossref,
  eLIBRARY), шаффл рецензентов — по силам студенческой команде.
- Боли 4–5 закрываются LLM-проверками: у команды есть компетенции
  (AI Engineer) и бюджет; правило «формальное — парсером, содержательное — LLM»
  снижает стоимость и риск.
- Антиплагиат и электронная подпись остаются внешними ручными процессами —
  сознательно не берём: нет API, есть юридические требования.

## Вне скоупа

Интеграция с вузовскими системами (1С, электронный кампус), антиплагиат,
электронная подпись, мобильное приложение.
