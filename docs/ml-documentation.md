# AI-часть ВКР-трекера

## От профиля до черновика

`POST /api/generate/selected` принимает список выбранных преподавателей с
`teacher_id` и `count`, а также необязательное поле `focus`. Backend читает
научные направления и прошлые темы из профиля. В обычной конфигурации
генератор отправляет числовой ID, направления, до 20 прошлых тем и обработанный
`focus`. ФИО и контакты в этот payload не добавляются. Учебные и реальные
профили следует заполнять без персональных данных в свободных текстах.

Контракт ответа модели для одного преподавателя:

```json
{"teachers":[{"teacher_id":7,"titles":["Разработка сервиса проверки библиографии"]}]}
```

В `lab5-exact-count-v1` запрос задаёт провайдеру `minItems = maxItems = count`
для массива `titles`. Генератор проверяет JSON Schema, соответствие ID, количество и длину тем,
повторы внутри ответа и признак обрезки. Backend вычисляет лексические
сигналы похожести и сохраняет темы как черновики. Подтверждение тем выполняет
человек. Поиск по внешним источникам в этом режиме отсутствует.

## Промпты, предобработка и параметры

| Настройка | Версия и назначение |
|---|---|
| `AI_PROMPT_VARIANT=v1` | `lab3-topics-v1` в [baseline.py](../ml/models/baseline.py), рабочий вариант по умолчанию и основа финального замера |
| `v2` | `lab4-topics-v2`, уточнённые инструкции о профильности, повторах и недоверенном вводе |
| `v2-compact` | `lab4-topics-v2-compact`, до шести уникальных прошлых тем |
| Фильтр `focus` | `lab5-focus-v1` в [focus.py](../ml/models/focus.py). Проверяет нормализованный текст на явные команды модели и маркеры ролей. Подозрительный `focus` удаляется целиком, запрос продолжается |
| Модель HTTP API | `MISTRAL_MODEL=ministral-8b-2512` по умолчанию, доступна `ministral-3b-2512` |
| Генерация | Температура 0,2, seed 42, лимит `min(8192, count * 120 + 100)`, до трёх попыток, HTTP-таймаут 40 с для отдельной попытки |
| Кэш | `AI_CACHE_TTL_SECONDS=0` по умолчанию. Для измеренного варианта демо взято 900 с. Кэш в памяти процесса и учитывает модель, версии промпта, схемы и фильтра и полный отправляемый контекст |

Причины изменений промпта и результаты A/B зафиксированы в
[ЛР4](experiments/lab4.md). В ЛР5 измерен вклад фильтра, точного ограничения
количества тем в схеме и кэша при одной версии системного промпта.
Задержка на один HTTP-вызов отличается от бюджета
запроса с повторами. Настройки соединения и формат примеров описаны в
[.env.example](../.env.example).

## Инструмент модели

`read_topic_history` по умолчанию выключен. Вход
`{"teacher_id":7,"limit":3}`, где ID положительный и лимит от 1 до 6.
Успех возвращает `{"status":"ok","titles":["…"]}`. Диспетчер проверяет
совпадение с профилем текущего запроса и разрешает читать только его темы.
Ответы об ошибке содержат статус `invalid_arguments`, `unknown_tool`,
`forbidden`, `timeout` или `unavailable`. Чтение ограничено 250 мс,
HTTP-раунд выбора функции — 5 с. При сбое продолжается обычная генерация.

Пилот запускается с `AI_PROMPT_VARIANT=v2`, `AI_HISTORY_TOOL=true`,
`AI_CACHE_TTL_SECONDS=0`. Контракт и команды доступны в
[документации инструмента](../ml/tools/README.md). В финальном эксперименте
инструмент выключен, его сквозной вызов покрыт тестом с MockTransport.

## Воспроизведение финальных метрик

1. Из рабочего клона с тегом `lab5-ai-eval-v2` открыть отдельную папку.
   Для локального запуска нужны Linux x86-64 или WSL2, Python 3.12, Git,
   curl и около 3 ГБ свободного диска под модель и движок.

   ```bash
   git worktree add --detach ../lab5-eval lab5-ai-eval-v2
   cd ../lab5-eval
   python3.12 -m venv .venv
   source .venv/bin/activate
   python -m pip install -r requirements-ai.txt
   ```

2. Запустить тесты и реальную локальную генерацию без API-ключа.

   ```bash
   python -m pytest -q
   bash scripts/run-lab5-local.sh lab5-ai-eval-v2 var/lab5-local-repro
   ```

   Скрипт скачивает закреплённые `llama.cpp b12292` и
   Ministral 3B Instruct 2512 Q4_K_M, проверяет их SHA-256 и запускает
   сервер на `127.0.0.1:8087` с контекстом 4096 и одним слотом. По
   умолчанию задействовано восемь CPU-потоков. Замер вычисляет p50/p95
   на машине запуска. Для повторного запуска укажите новый каталог результатов.

3. Сверить `summary.json` с [зафиксированным прогоном](experiments/results/lab5-local-ministral3b/).
   В `requests.csv` лежат замеры на запрос, в `attempts.jsonl` — статусы,
   задержка и токены каждой LLM-попытки, в `answers.jsonl` — темы.
   Хэш датасета и системного промпта записаны в итогах.
   [Ноутбук](../notebooks/lab5-ablation.ipynb) читает эти файлы с ветки сдачи.

Для прогона без точного ограничения числа тем используйте отдельный
worktree тега `lab5-ai-eval-v1` и передайте тот же тег в скрипт. Его
[результаты](experiments/results/lab5-local-pre-schema/) сохранены отдельно.
Исторический A/B ЛР4 воспроизводится на коммите `ed15a09`.

Для быстрой проверки пайплайна CI запускает тот же runner с `--mode mock`.
Для облачного замера задать в окружении `MISTRAL_API_KEY` и нужную
`MISTRAL_MODEL`, затем запустить:

```bash
python -m ml.experiments.lab5 --mode live --tag lab5-ai-eval-v2 --output var/lab5-cloud
```

Облачный API может списывать плату. Флаги `--input-rate` и `--output-rate`
принимают фактический тариф в USD за миллион токенов. При неизвестном тарифе
или неполном usage стоимость в итогах остаётся пустой. Для обычного запуска
сервис поддерживает локальные трейсы и Langfuse. Эксперимент пишет локальные
метаданные без содержимого промптов и использует синтетические профили.
