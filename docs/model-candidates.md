# Model Candidates — решение Lab 2

> Этот документ фиксирует решение по модели. Это не ADR архитектуры:
> модель, её цена и план деградации фиксируются отдельно, как требует Lab 2.

## 1. Контекст

AI-сценарий проекта — генерация кандидатов тем ВКР по:

- научным направлениям преподавателя;
- прошлым одобренным темам;
- направлению 09.03.01;
- дополнительному focus администратора.

После генерации результат проверяется локальным Quality Gate и человеком.

В Lab 1 рассматривались облачные модели и локальные альтернативы. Для MVP нужен один основной
вариант, чтобы измерения качества были воспроизводимыми.

---

## 2. Решение

**Основная модель MVP: Ministral 3 8B (`ministral-8b-2512`).**

Причины:

1. модель уже интегрирована и проверена в прототипе;
2. поддерживает Chat Completions;
3. поддерживает Custom Structured Outputs;
4. контекст 256k значительно превышает текущую потребность одного профиля;
5. цена позволяет выполнять массовые эксперименты;
6. один model id фиксируется на весь batch, что позволяет честно сравнивать качество.

Официальная карточка модели:

- https://docs.mistral.ai/models/ministral-3-8b-25-12

Structured Outputs:

- https://docs.mistral.ai/studio/conversations/structured-output/custom

---

## 3. Цена основной модели

Актуальная цена Ministral 3 8B на момент подготовки решения:

- input: **$0.15 / 1M tokens**;
- output: **$0.15 / 1M tokens**.

Источник:

- https://docs.mistral.ai/inference/pricing

Для консервативного бюджета одного сценария из Lab 1:

- 6000 input tokens;
- 2000 output tokens.

Расчёт:

- input: `6000 × 0.15 / 1 000 000 = $0.0009`;
- output: `2000 × 0.15 / 1 000 000 = $0.0003`.

**Итого: ≈ $0.0012 за сценарий.**

После перехода на компактный `titles[]` фактический output обычно должен быть меньше этого
консервативного бюджета; точное потребление необходимо логировать из поля `usage` ответа API.

---

## 4. Дешёвая модель для деградации

**Degraded model: Ministral 3 3B (`ministral-3b-2512`).**

Официальная карточка:

- https://docs.mistral.ai/models/ministral-3-3b-25-12

Цена:

- input: **$0.10 / 1M tokens**;
- output: **$0.10 / 1M tokens**.

Источник:

- https://docs.mistral.ai/inference/pricing

Для того же бюджета 6000 + 2000 токенов:

`8000 × $0.10 / 1 000 000 = $0.0008`.

То есть расчётная API-стоимость примерно на **33% ниже**, чем у 8B.

---

## 5. План деградации

Деградация не должна быть скрытым переключением модели внутри обычного batch.

### Нормальный режим

```text
ministral-8b-2512
        ↓
Structured Output
        ↓
Quality Gate
```

Если 8B не отвечает после ограниченного retry/timeout:

- текущая AI-операция завершается явной ошибкой;
- локальный demo-банк не используется как замена;
- пользователь может повторить запрос.

### Явный degraded mode

Если 8B длительно недоступна или требуется более дешёвый эксперимент:

```text
новый batch
   ↓
ministral-3b-2512
   ↓
обязательный provenance
   ↓
Quality Gate
   ↓
manual review
```

Правила degraded mode:

1. фактическая модель сохраняется в `generation_model`;
2. `generation_source` остаётся `mistral-ai`;
3. весь экспериментальный batch желательно выполнять одной моделью;
4. темы 3B не утверждаются автоматически;
5. результаты 3B и 8B сравниваются отдельно;
6. если качество 3B ниже заданного порога, degraded mode используется только для черновиков.

В текущем прототипе автоматический small-model fallback по умолчанию выключен
(`MISTRAL_ALLOW_SMALL_FALLBACK=false`) именно для сохранения воспроизводимости.

## 6. Цена решения — не только токены

### Денежная цена

- основной сценарий 8B: около `$0.0012` при консервативном бюджете 6000 + 2000;
- degraded 3B: около `$0.0008` при том же бюджете;
- отдельные AI-repair запросы увеличивают расход.

### Конфиденциальность

Профиль преподавателя и прошлые темы передаются внешнему AI-провайдеру.
Поэтому в контекст не должны попадать лишние персональные данные, секреты и полные тексты,
которые не нужны для задачи.

### Доступность

Решение зависит от:

- внешней сети;
- Mistral API;
- rate limits;
- latency провайдера.

Поэтому локальный demo-режим отделён от AI-режима и никогда не маскирует сбой Mistral.

### Инфраструктура

Помимо LLM требуется поддерживать:

- versioned prompt;
- JSON Schema;
- retry / timeout;
- provenance;
- локальный профильный scorer;
- локальные embeddings;
- Quality Gate;
- ручное подтверждение;
- мониторинг latency и token usage.

### Цена качества

Более дешёвая модель может давать больше:

- профильных промахов;
- перефразированных дублей;
- AI-repair;
- ручной работы.

Поэтому минимальная цена API сама по себе не является критерием выбора модели.

---

## 7. Что должно заставить пересмотреть решение

Решение пересматривается, если выполняется хотя бы одно условие:

- доля тем без ручного предупреждения стабильно ниже 80%;
- средний batch требует более одного AI-repair на преподавателя;
- timeout/error rate выше 5% на серии из не менее 100 запросов;
- стоимость ручной проверки становится выше экономии на дешёвой модели;
- появляется требование не отправлять профиль во внешнее облако;
- локальная модель достигает сопоставимого качества на golden dataset.

---

## 8. Статус

**Accepted for MVP / Lab 2.**

Основная модель: `ministral-8b-2512`.

Деградация: явный отдельный запуск на `ministral-3b-2512`, без скрытого смешивания моделей.
