# Iteration notes — что изменилось после прототипа (спринт 3)

Дата: 30.10.2026. Роль: Product/VO.
Вход: `docs/use-cases/validation-log.md` (валидация UC, разрывы R1–R8),
`docs/quality/eval-report-1.md` (таксономия ошибок), прототип PR #6.

Правило спринта: изменения требований — **явными правками**, не молча.
Ниже каждая правка с мотивом и ценой.

## 1. Явные правки требований

### Правка 1. Генерация тем: из не-скоупа — в легализованный UC-07

- **Было (роадмап):** «Генератор тем по профилю преподавателя (AI-пайплайн,
  ADR-001) — веха 2: сначала каталог на переносе и ручном вводе тем».
- **Стало:** UC-07 добавлен в индекс (`docs/use-cases/README.md`), UC-02
  обновлён до v2 (шаг 2 — AI-кандидаты, поток А3 — каталог не блокируется
  генерацией). Роадмап правится так: в скоупе MVP появляется строка
  «UC-07 — прототип-валидация концепции в спринте 3», поставка в пилот
  остаётся вехой 2.
- **Почему:** прототип спринта 3 уже реализовал эту фичу целиком
  (`ml/`, `backend/routers/ai.py`, контракт). Удалить её или «не заметить»
  нельзя; спрятать — значит оставить команду строить UI по несуществующей
  спеке. Легализация с явной границей («прототип-валидация ≠ пилотная
  поставка») сохраняет план вех и честно описывает реальность.
- **Цена:** веха M1 (UC-01 + UC-06, неделя 6) не закрыта прототипом —
  Delivery строит контур цикла от нуля (разрыв R1). Смягчение: задачи D-1
  в спринте 4 приоритетнее любых доработок генерации.

### Правка 2. Quality Gate: двухсостояний в спеке, «passed» только после человека

- **Было (`ai-pipeline.md`):** gate выдаёт `passed / review / blocked`.
- **Стало:** gate выдаёт `blocked` / `review`; `passed` возникает только
  после ручного approve. Правка заходит в `ai-pipeline.md` v2 в спринте 4
  (совместно с AI, разрыв R3).
- **Почему:** код (`quality.py`) уже работает консервативно и это правильно
  для продукта: ни одна тема не попадает в каталог без решения человека.
- **Цена:** отсутствует — правка описывает фактическое поведение.

### Правка 3. SLO для генерации тем (R7)

- **Было:** в PRD заданы цены/латентности только для рефчекера, LLM-нормоконтроля
  и LLM-ревью кода.
- **Стало:** в UC-07 заданы SLO: пакет ≤ 5 тем — ≤ 40 c с повторами;
  ≤ 0,1 ₽ за сценарий (расчёт model-candidates: ≈ $0,0012). Бюджет пилота
  (≤ 3 000 ₽) не затронут: генерация тем по 15–30 руководителям стоит
  порядка 1–3 ₽ за полный цикл.
- **Почему:** без SLO нельзя отличить «медленно из-за повторов» от
  «медленно всегда» в живом прогоне.

### Правка 4. Актёр и источник профилей (R6)

- **Было:** пайплайн — актёр «Администратор/кафедра», профили из JSON-файла.
- **Стало:** UC-07 фиксирует актёра «Руководитель ВКР» (как в UC-02);
  JSON-файл — режим прототипа, в MVP профиль читается из таблиц
  `teachers`/`past_topics` общей БД.
- **Почему:** два разных актёра на одну фичу — дефект спеки; сегмент PRD —
  замзав, но наполнение каталога делает руководитель.

## 3. Техдолг: что оставляем сознательно и по какой цене

| Долг | Почему оставляем | Цена владения | Когда закрываем |
|---|---|---|---|
| Lexical-only similarity (без embeddings) | Дешёвый и детерминированный prescreen; live-прогон сначала должен показать долю E3 | Перефразированные дубли доходят до человека; ручной approve страхует | Веха 2, после live-метрик |
| SQLite-адаптер вместо Postgres/Supabase | Позволил проверить сохранение без инфраструктуры | Отдельная схема, не миграции; закрывается S4-7 | Спринт 4 |
| Профили из JSON-файла | Прототип не зависел от учётки руководителя | Ручной подвод данных; закрывается S4-1/S4-7 | Спринт 4 |
| Mock-токены и mock-latency | Честный протокол эксперимента (is_model_benchmark=false) вместо выдуманных цифр | Цифр экономики нет до live-прогона | Спринт 4 (S4-5) |
| Retrieval отсутствует | Решение лабы 2: профиль помещается в промпт | Ограничение корпуса 20 тем; не мешает MVP | Веха 2+ (по росту корпуса) |

## 4. Ответ на вопрос спринта: «Работает ли концепция?»

**Частично, с явной границей.**

- Работает и доказано тестами: контур AI-части — structured output с
  повторами, консервативный gate, сохранение с provenance, атомарность
  пакета, контракт и 23 теста (mock).
- Не доказано: качество самих тем (live-вызов не выполнен), доставка
  трейсов в Langfuse, ценность для руководителя (экспертная оценка).
- Концепция «LLM-кандидаты + обязательный человек-approve» согласована
  с кодом и UC — это и есть главная ставка спринта, теперь она
  задокументирована и измерима в спринте 4.
