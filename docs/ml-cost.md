# Стоимость генерации тем ВКР

Сценарий: семь кейсов, каждый вызван дважды с теми же входными данными.
Цена по API считается отдельно для входа и выхода. Кэш включён только у C.

| Показатель | A, v1 без кэша | C, v2-compact с кэшем |
|---|---:|---:|
| Запросов приложения | 14 | 14 |
| HTTP-вызовов провайдера в контрольном прогоне | 14 | 7 |
| Попаданий в кэш | 0 | 7 |
| Байты содержимого сообщений во всех вызовах | 17 164 | 10 497 |
| Входные токены по локальному токенизатору | 3 192 | 1 900 |
| Расчёт цены входа при условной ставке 0,10 USD/млн | 0,0003192 USD | 0,0001900 USD |
| Фактический usage Mistral и счёт | Не измерены | Не измерены |

Для повторного запроса с попаданием в локальный кэш оплачиваемые токены
равны нулю: исходящего HTTP-вызова нет. Суммарный эффект зависит от доли
повторных запросов и относительной цены холодного вызова. На холодном
прогоне сокращение истории уменьшило объём B на 702 байта, но C
отправил на 1 915 байт больше исходного A из-за расширенных инструкций.
Байты — размер текста, а не оценка количества токенов.

Токенизатором Ministral 8B подсчитаны входные токены сформированных
запросов. В сценарии повторов C использовал на 40,5% меньше расчётных
входных токенов. В холодном сценарии у A — 1 596, у B — 2 002, у C —
1 900. C уменьшает объём B на 5,1%, при этом холодный C дороже A по
входу. Условная ставка показывает расчёт при одинаковой цене входа.
Она не утверждает тариф Mistral. В оценку не входит цена выходных токенов.

Токенизатор `tekken.json` доступен в [репозитории модели Ministral 8B](https://huggingface.co/mistralai/Ministral-3-8B-Instruct-2512).
SHA-256 файла записан в `summary.json`. Для воспроизведения расчёта:

```bash
python -m pip install mistral-common==1.13.1
python -m ml.experiments.lab4 --mode mock --output var/lab4-token-estimate --tokenizer-file tekken.json --input-rate 0.1 --output-rate 0.1
```

После настройки API-ключа передать действующие ставки выбранной модели
в USD за миллион токенов:

```powershell
python -m ml.experiments.lab4 --mode live --output docs/experiments/results/lab4-live --input-rate $InputRate --output-rate $OutputRate
```

Формула: `(input_tokens × input_rate + output_tokens × output_rate) / 1_000_000`.
Usage берётся из HTTP-ответа. При пропущенном usage суммарная стоимость
остаётся пустой. Режим инструмента использует дополнительный вызов и
выключен в эксперименте, чтобы измерить эффект промпта, контекста и кэша.
