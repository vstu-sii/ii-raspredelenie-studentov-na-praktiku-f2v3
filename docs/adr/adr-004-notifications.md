# ADR-004: Уведомления через очередь с исполнителями

**Статус:** принято · **Дата:** 2026-09-29 · **Решают:** команда

## Контекст
Напоминания — ядро ценности (H2, North Star). По инсайту интервью №4
уведомления должны приходить туда, где человек уже живёт: почта
и мессенджер, а не «ещё один портал». Каналы капризные: лимиты,
задержки, недоступность.

## Решение
Планировщик создаёт события напоминаний в таблице-очереди `notifications`.
Исполнители — два воркера: email и мессенджер-бот. Воркеры повторяют
доставку с паузой, недоставленное остаётся в очереди с флагом ошибки.

## Альтернативы
- Слать напрямую из обработчиков запросов — отклонено: падение канала
  роняет пользовательский сценарий; напоминания теряются молча.
- Внешний брокер (RabbitMQ/Kafka) — отложено: для объёмов пилота
  таблица в Postgres достаточна; переезд на брокера — механический.

## Цена решения
Таблица-очередь вместо брокера — компромисс: при росте объёмов
потребуется миграция на настоящий брокер. Берём правило: очередь
мониторится (длина, возраст старейшего события) с вехи M1 — иначе
тихая недоставка подорвёт H2, а мы узнаем постфактум.
