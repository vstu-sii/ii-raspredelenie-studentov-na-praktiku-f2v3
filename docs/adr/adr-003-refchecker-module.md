````markdown
# ADR-003: Рефчекер — модуль внутри бэкенда

**Статус:** принято · **Дата:** 2026-09-29 · **Решают:** команда

## Контекст
Рефчекер — самый нагруженный внешний вызов: DOI/ISBN/URL → запросы
в Crossref/eLIBRARY → сборка ГОСТ-строки. Лимит PRD: ≤ 5 с и ≤ 0,1 ₽
на источник. Вопрос: отдельный сервис или модуль?

## Решение
Модуль `refchecker` внутри бэкенда (см. ADR-002) с собственным кэшем
метаданных в Postgres: повторный запрос по тому же DOI не ходит наружу.

## Альтернативы
- Отдельный сервис сразу — отклонено: один потребитель (бэкенд),
  вынос окупится только при росте нагрузки или появлении второго
  потребителя.
- Без кэша — отклонено: студенты будут добавлять одни и те же источники,
  внешний API забанит за частые запросы.

## Цена решения
Кэш требует политики инвалидации — принимаем «вечный кэш» (метаданные
DOI не меняются), за это платим: исправление ошибки в метаданных
требует ручной чистки кэша. Второй долг: eLIBRARY без стабильного
открытого API — на старте источник работает через ручной импорт,
флаг «источник не распознан» (А1 из UC-04) покрывает этот случай.
````
