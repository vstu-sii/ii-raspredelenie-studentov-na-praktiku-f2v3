# ADR-001: AI-подход — structured prompt + отдельный Quality Gate

**Статус:** принято · **Дата:** 2026-09-11 · **Решение:** AI Engineer (лаба 1)
**Первоисточник:** docs/research.md (ветка lab1-ai-engineer-initiation), разделы 1–10

## Контекст
AI-функция каталога: генерация тем ВКР по профилю преподавателя и его прошлым
одобренным темам. Ресёрч лабы 1 сравнил три подхода: прямой вызов LLM
со структурированным промптом, RAG, AI-агент.

## Решение
Пайплайн: профиль преподавателя + прошлые темы → LLM со structured prompt
(JSON Schema, Structured Outputs) → **отдельный Quality Gate** → ручное
подтверждение руководителем. Quality Gate не доверяет самой LLM: проверки
семантических дублей и соответствия профилю — через embeddings, поверх ответа
модели. RAG в MVP не входит (корпус мал: профиль + список тем — целиком
в контексте), AI-агент не используется (последовательность шагов известна
заранее, автономность не нужна).

## Альтернативы
- RAG сразу — отклонено: инфраструктура (база знаний, vector storage,
  обновление индекса) раньше необходимости; возвращаемся при большом
  корпусе — методички, архив ВКР, публикации.
- AI-агент — отклонено: пайплайн фиксирован, агент добавил бы управление
  состоянием без решения проблемы качества генерации.
- LLM как единственный контролёр качества — отклонено по результатам
  эксперимента: модель переформулирует существующие темы другими словами,
  поэтому решение о качестве темы принимается вне LLM.

## Цена решения
Четыре долга: (1) денежная — зависит от реального объёма токенов, бюджет
сценария считается заранее; (2) передача данных во внешнее облако — профиль
и темы уходят провайдеру, в промпты не включаем лишние персональные данные;
(3) зависимость от внешнего API — rate limits и доступность, плюс
географические ограничения провайдеров (OpenAI исключён: Россия не в списке
поддерживаемых стран — эксплуатационный риск); (4) инфраструктурная —
поддержка промптов, JSON Schema, embeddings и мониторинга лимитов.
