# Роадмап: ВКР-трекер

Скоуп собран из use cases (docs/use-cases/). Правило спринта: не-скоуп
важнее скоупа — всё, что не попало в MVP, не двигает сроки и не ползёт
в разработку самовольно.

## Скоуп MVP (пилот на одной кафедре, текущий учебный год)

| UC | Что строим | Зачем сегменту |
|---|---|---|
| UC-01 | Запуск цикла: окна регламента, автораскладка дедлайнов, план напоминаний | Замзав открывает цикл за минуты, а не за неделю переписок |
| UC-02 | Каталог тем: перенос тем прошлых лет, вписывание новых, публикация | Темы не теряются в мессенджерах, статус наполнения виден |
| UC-03 | Подача пар «студент — тема» и автосборка проекта приказа | Проект приказа ≤ 1 дня после подачи всех пар (H1) |
| UC-04 | Рефчекер: DOI/ISBN/URL → строка по ГОСТ, проверка состава списка | Список литературы собирается без ручного форматирования (H3) |
| UC-05 | Просмотры: шаффл рецензентов, карточки, напоминания при просрочке | Просрочка видна в день возникновения (H2) |
| UC-06 | Дашборд цикла: статусы этапов, просрочки, история напоминаний | «Кто застрял» — за один экран; данные для North Star |
| UC-07 | Генерация кандидатов тем по профилю: **прототип-валидация концепции — спринт 3** (лаба 3, PR #6); пилотная поставка — веха 2 (см. не-скоуп и iteration-notes) | Снимает боль «пустого листа» при новом направлении работы руководителя |

Инфраструктура MVP: FastAPI + Postgres, dev-окружение из compose, CI,
прод с автодеплоем — база заложена в лабе 1 и наращивается здесь.

## Не-скоуп (явно, не делаем)

- **Генератор тем по профилю преподавателя — пилотная поставка** (AI-пайплайн,
  ADR-001) — веха 2: сначала каталог на переносе и ручном вводе тем.
  Правка 30.10 (спринт 3, iteration-notes): прототип-валидация концепции
  выполнена в спринте 3 на живом коде (UC-07, PR #6) — это НЕ перенос
  поставки в MVP: до вехи 2 фича не получает UI, миграций и статусов
  пилота, доработки только по задачам S4-3/S4-4
- **LLM-ревью кода** (архив → замечания по файлам) — веха 2, после пилота MVP:
  сначала трекерная ценность, затем AI-проверки
- **LLM-нормоконтроль PDF** (содержательная сверка с методичкой) — веха 2,
  та же причина
- **Антиплагиат** — внешняя ручная проверка со справкой, вне скоупа всегда:
  нет API, есть юридические требования
- **Электронная подпись** — вне скоупа всегда: юридические требования
- **Интеграция с вузовскими системами** (1С, электронный кампус) — вне скоупа:
  нет доступа к API, согласование дольше семестра
- **Мобильное приложение** — вне скоупа: сегмент сидит за рабочим компьютером
- **Парсинг PDF** (разделы, поля, шрифты) — — детерминированная частьнормоконтроля; будет оформлен отдельным ADR в вехе 2,  в   MVP не входит
- **Личные кабинеты нормоконтролёра и библиотеки** — их шаги в MVP
  фиксируются статусами, отдельные интерфейсы не строим

Не-скоуп пересматривается только решением команды с записью в роадмап —
не «понеслось» из обсуждений.

## Вехи до Demo Day

| Веха | Срок | Что должно работать | Как проверяем |
|---|---|---|---|
| M1. Каркас цикла | неделя 6 | UC-01 + UC-06: цикл запускается, дашборд показывает этапы | Разыгрывание UC на демо |
| M2. Темы и приказ | неделя 8 | UC-02 + UC-03: каталог опубликован, проект приказа собирается | Сборка проекта на тестовых парах ≤ 1 дня |
| M3. Рефчекер | неделя 10 | UC-04: DOI → ГОСТ-строка, проверка состава списка | Golden dataset v1: точность строк ≥ 90 % |
| M4. Просмотры | неделя 12 | UC-05: шаффл, карточки, напоминания при просрочке | Просрочка видна в день возникновения |
| M5. Пилотная готовность | неделя 14 | Весь MVP на тестовых данных кафедры, прод стабилен | Прогон полного цикла UC-01→UC-06 |

Между вехами — приёмка по DoD (docs/quality/dod.md): веха закрыта,
когда её критерии проверены, а не «кажется, готово».
