# Архитектура — ВКР-трекер (MVP)

Чертежи системы as-code: исходники диаграмм лежат рядом и меняются
вместе с кодом. Диаграмма без исходника в репо не существует.

## Уровни C4

| Уровень | Файл | Что показывает |
|---|---|---|
| Context | c4-context.puml | Система в целом: кто пользуется, с чем обменивается данными |
| Container | c4-container.puml | Состав системы: 5 контейнеров, их технологии и связи |

Container-уровень разворачивает «ВКР-трекер» из Context: каждый контейнер
ссылается на ADR, которым решено его появление (docs/adr/).

## Состав системы (container-уровень)

1. **Веб-интерфейс** — экраны всех UC, без сборщиков и фреймворков в MVP
2. **Трекер-бэкенд** — монолит FastAPI (ADR-002) с модулями tracker,
   catalog, refchecker, scheduler, notify
3. **Postgres** — Supabase на проде, локальный в compose на dev (ADR-005)
4. **Email-воркер** и **воркер мессенджера** — исполнители очереди
   уведомлений (ADR-004)

## Проверка машиной (aact)

Требование шага: aact check — 0 violations. Конфиг правил — aact.yml
в этой папке, запуск:

    aact check docs/architecture/aact.yml

Проверяемые правила:
- связи контейнеров не ссылаются на несуществующие контейнеры;
- у каждого контейнера заполнены технология и ответственность;
- нет связей «напрямую в чужую таблицу» в обход модуля-владельца.

## Соответствие решениям и скоупу

- В MVP нет ни одного AI-контейнера: генератор тем (ADR-001) и LLM-этапы
  — веха 2 (docs/roadmap.md)
- Очередь уведомлений — таблица в Postgres, не внешний брокер (ADR-004)
- Файлы (PDF, архивы кода) не хранятся в MVP — поле ссылок в схеме
  задел под веху 2 (ADR-005)
