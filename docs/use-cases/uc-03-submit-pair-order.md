# UC-03: Подать пару и собрать проект приказа

**Актёр:** Секретарь кафедры (вторичные: руководитель ВКР, замзав; внешний: ректорат)
**Цель:** Собрать проект приказа из поданных пар «студент — тема» и отправить его в ректорат за один день — вместо недели ручного сведения таблиц и пересборок Word-документа.
**Контекст:** Октябрь, второй круг подачи: руководитель указывает фамилию студента и итоговую формулировку темы, которая пойдёт в диплом.
**Триггер:** Руководитель подал пару «студент — тема».
**Предусловие:** Тема закреплена в каталоге (UC-02).

## Шаги
1. Руководитель открывает карточку своей темы в каталоге и подаёт пару:
   студент + итоговая формулировка темы для диплома.
2. Система фиксирует пару и показывает замзаву прогресс подачи:
   сколько пар из ожидаемых уже подано.
3. Когда все пары поданы (или окно подачи закрыто), система собирает
   проект приказа: номера тем, руководители, шифры ВКР.
4. Секретарь проверяет проект в системе и отправляет его в ректорат.
5. Система фиксирует ответ ректората: подписан / есть замечания.
6. Система публикует подписанный приказ и фиксирует статусы тем
   «утверждена».

## Результат
Проект приказа собран и отправлен в ректорат ≤ 1 дня после подачи всех пар
(цель PRD, гипотеза H1). Статусы тем в трекере соответствуют приказу.

## Альтернативные потоки
А1. Ректорат вернул проект с замечаниями: система ставит задачу
    руководителю со сроком, руководитель правит формулировку темы,
    система пересобирает проект за минуту — возврат к шагу 4.
А2. Окно подачи закрылось, а не все пары поданы: система собирает проект
    из поданных пар, неподавшие руководители видны замзаву на дашборде
    (UC-06); по заявлению от студента тема добавляется через смена темы.

## Связи
Боль PRD №1 (ручная сборка проекта приказа, 2–3 итерации пересборок).
Предусловие — каталог тем (UC-02). Потребитель результата — ректорат.
