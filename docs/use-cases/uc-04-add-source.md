# UC-04: Добавить источник через рефчекер

**Актёр:** Студент
**Цель:** Получить готовое библиографическое описание по ГОСТ Р 7.0.5-2008 за секунды — вместо ручного форматирования по 15–30 минут на источник с последующими возвратами от библиотеки.
**Контекст:** Второй семестр, студент собирает список литературы: ≥ 30 источников, ≥ 20 % зарубежных, обязательные базы — библиотека вуза, eLIBRARY, Scopus, интернет-источники.
**Триггер:** Студент нашёл источник и знает его DOI, ISBN или URL.
**Предусловие:** У студента есть работа, закреплённая в цикле (приказ UC-03 подписан).

## Шаги
1. Студент открывает свой список литературы в трекере и вставляет
   в поле рефчекера DOI, ISBN или URL источника.
2. Система запрашивает метаданные во внешних базах (Crossref, eLIBRARY,
   каталоги библиотек) и собирает строку описания по ГОСТ Р 7.0.5-2008
   — целевое время ≤ 5 с, цена ≤ 0,1 ₽ за источник.
3. Студент проверяет предложенную строку и добавляет её в свой список
   литературы одним нажатием.
4. Система сама проверяет состав списка против требований методички:
   объём, доля зарубежных, наличие обязательных баз — и показывает статус.
5. Библиотека подключается позже, отдельным шагом перед сшиванием работы:
   список уходит ей на проверку и подпись уже собранным.

## Результат
Источник добавлен готовой строкой ГОСТ за секунды. Студент сразу видит,
чего в списке не хватает, — без ручного пересчёта и без возвратов
на переделку.

## Альтернативные потоки
А1. Метаданные по идентификатору не найдены: система сообщает, что источник
    не распознан, и открывает ручной ввод — строка всё равно собирается
    по шаблону ГОСТ из введённых полей.
А2. Список не соответствует требованиям: система перечисляет конкретные
    пробелы — сколько источников добавить, каких баз не хватает,
    какая доля зарубежных сейчас.

## Связи
Боли PRD №3 (ручная проверка 1200+ позиций) и №5 (студенты не умеют
оформлять по ГОСТ). Первые примеры golden dataset — из интервью №2:
вход URL → эталон ГОСТ-строка.
