# UC-07: Сгенерировать кандидатов тем по профилю преподавателя

> Новый UC по итогам валидации прототипа (спринт 3, см. `validation-log.md`,
> разрыв R2). Прототип (PR #7, ветка lab3-ai-engineer-prototype) реализовал
> эту фичу целиком; в UC лабы 2 её не было, а роадмап относил генератор тем
> к вехе 2. Статус фичи для пилота: **прототип-валидация концепции**,
> поставка в MVP — решение спринта 4 (см. `../iteration-notes.md`).

> **Обновление v3 (12.11.2026, спринт 4).** Статус фичи зафиксирован в
> `../mvp-scope.md`: поставка в MVP — веха 2, в спринте 4 достраиваются
> только approve/export (A-1/A-2), `ai-pipeline.md` v2 (R3) и тексты причин
> на языке пользователя (R8). A/B промптов 11.11.2026 (PR #10, локальный
> прогон Ministral-3B, разметка вслепую): по умолчанию остаётся v1 — 7/7
> валидных пакетов против 5/7 у v2 и v2-compact; v2 снял смысловой дубль
> на парных кейсах (1/9 → 0/9) и следование инъекции в `injection-json`,
> но потерял два валидных пакета и одну конкретную тему. Варианты
> v2/v2-compact — кандидатами через `AI_PROMPT_VARIANT`; переход — при
> подтверждённом приросте (ADR: `../ml-changes.md`). Кэш генерации:
> TTL = 0 по умолчанию, ручная перегенерация кэш обходит; инструмент
> `read_topic_history` выключен по умолчанию. Live-факт облачного контура
> 30.10 — в таблице SLO ниже.

**Актёр:** Руководитель ВКР (инициирует и подтверждает); система выполняет
генерацию. Вторичный: замзав видит статус наполнения каталога (связь с UC-02).

**Цель:** Получить осмысленных кандидатов формулировок тем ВКР по профилю
преподавателя за секунды — вместо пустого листа при вписывании с нуля и
вместо свальных тем прошлых лет, которые не соответствуют текущим
направлениям работы.

**Контекст:** Сентябрь, окно наполнения каталога (UC-01). Прототип —
детерминированный пайплайн ADR-001: профиль → LLM (Mistral,
structured output) → локальный Quality Gate → ручное подтверждение.
Без retrieval: профиль и до 20 прошлых тем передаются в промпт напрямую.

**Триггер:** Руководитель нажимает «Сгенерировать кандидатов» в карточке
наполнения каталога.

**Предусловие:** Профиль преподавателя существует в системе: научные
направления, темы прошлых лет (в прототипе — JSON-профиль через
`AI_PROFILE_PATH`, в MVP — записи в `teachers`/`past_topics`).

## Шаги

1. Руководитель выбирает преподавателей, количество тем на каждого и
   необязательный фокус (например, «автоматизация цикла ВКР»).
2. Система формирует ограниченный контекст профиля (направления, прошлые
   темы, без ФИО и контактов) и вызывает LLM со structured output —
   ответ строго `teacher_id + titles[]`.
3. Локальный Quality Gate проверяет каждого кандидата: точный дубль →
   `blocked` (score 100), лексическая близость к прошлым темам ≥ 50 →
   `blocked`, 25–50 → пометка «возможный дубль»; короче 7 слов →
   «слишком общая»; нет лексического пересечения с направлениями →
   «не совпадает с профилем». Все неблокированные кандидаты получают
   `review` — ручное подтверждение обязательно.
4. Система сохраняет кандидатов в БД со статусом `draft`, provenance
   (модель, промпт-версия) и метаданными качества (similarity к ближайшей
   прошлой теме: своей, чужой, в пакете).
5. Руководитель просматривает кандидатов и подтверждает (`approve`),
   правит или отклоняет — решение фиксируется в БД. Перегенерация одного
   кандидата — отдельным действием (кэш при ручной перегенерации
   обходится).
6. Approved-темы попадают в каталог (UC-02); draft/blocked в каталог
   не попадают.

## Результат

Руководитель получает рабочий список кандидатов за секунды вместо пустого
листа. Ни одна тема не попадает в каталог без явного решения человека.
Каждый вызов LLM виден в трассировке (промпт и ответ).

## Альтернативные потоки

А1. Ошибка/timeout/429 от провайдера: до трёх повторов, затем явная ошибка
    пользователю; пакет не сохраняется частично (атомарность), demo-банк
    тем не подмешивается в AI-результат.
А2. Модель вернула невалидный structured output: попытка повторяется,
    невалидный ответ не сохраняется.
А3. Prompt injection через поле фокуса (кейс в seed Quality): система не
    обязана защищать провайдера, но не должна выполнять инструкции из
    пользовательского текста; кейс проверяется живым прогоном и попадает
    в eval-report. (v3) Факт A/B 11.11: v1 исполнил внедрённую команду
    в `injection-json` (маркер `CANARY-LAB4`), v2/v2-compact — нет; второй
    инъекционный кейс не засчитан: у кандидатов нет валидных ответов.
    Требование к публичному контуру — PRD v3, «Лимиты, права и
    безопасность модели».
