# План Б демо

## AI

### До выступления

На машине показа держать код демо-тега, входы, `backup.json` и
`summary.json` из [папки результатов](results/lab6-local/).
Файл содержит проверенные ответы первого раунда. Его хэш записан
в сводке. Ключ Mistral в материалы демо не включается.
Перед показом выполнить репетицию ключевых запросов в том же процессе
API. Кэш настроен на 900 с и хранится в памяти процесса.

### Прогретый кэш

При отказе провайдера повторить тот же запрос, сохранив профиль,
версию модели, промпта и схемы. Пока запись действительна, генератор
возвращает проверенный черновик без обращения к модели. На сцене сказать
«Этот ответ получен из кэша предыдущего запроса».
По истечении TTL, после перезапуска процесса или изменения входа потребуется
обращение к провайдеру. Кнопка регенерации обходит кэш.

### Пустой кэш или перезапуск

При недоступности провайдера обычный endpoint отвечает HTTP 503,
после ограниченных попыток. Стрим завершает ответ событием `error`
с нулевым количеством созданных тем. Набор тем остаётся пустым.
Не повторять запрос из зала бесконечно. Открыть сохранённый ответ командой:

```bash
python -m ml.experiments.lab6 --replay docs/demo/results/lab6-local --case databases
```

Вывод явно содержит `mode=recorded_demo`, исходный запрос, модель,
тег и коммит прогона. Этот режим только читает файл и подходит для показа
в терминале. Во время показа сказать «Провайдер сейчас недоступен.
Показываю сохранённый результат репетиции на этой версии».

### Что проверено

Runner имитирует HTTP 503, сетевой таймаут и HTTP 401 на границе провайдера
после настоящего прогрева кэша. Проверяются ответы API, число ретраев,
целостность БД и событие ошибки стрима. Инъекция таймаута срабатывает
мгновенно. Продолжительность реального сетевого зависания определяется
таймаутом 40 с на попытку, поэтому значение из проверки не является
гарантированным верхним пределом при обрыве сети.

[Протокол](../demo-run.md) содержит измеренные времена и число проверок.
Встраивание сохранённых ответов в общий UI требует интеграции Delivery.

## Командная подготовка

Delivery подтверждает публичный URL и развёрнутый тег, готовит запасной
интернет и доступ к видео Product. Product проверяет открытие видео
и распределяет реплики при переключении. В этом AI-протоколе записаны
проверки генератора и API. Репетиция общего продукта с прода, видео
и два полных десятиминутных прогона фиксируются командой отдельно.
